Security Rules

Applied automatically based on the district the customer selects at checkout.

Customers can choose Cash on Delivery or bKash at checkout. For bKash, they'll enter their number and Transaction ID for you to verify.

—
To authorize a new admin: have them sign in once with their own Firebase Auth account (they'll be blocked), copy their UID from the browser console error or Firebase Console → Authentication, then add it under admins/<uid>: true in the Realtime Database. The first person to ever sign in is auto-registered as the founding admin.

Apply these rules in your Firebase Console → Realtime Database → Rules. Public visitors can only read products/categories and create new orders (never edit or delete existing ones) — all other writes require a signed-in, allow-listed admin. Product images are compressed and stored as base64 strings inside products — no Firebase Storage setup is needed.

{
  "rules": {
    "admins": {
      ".read": "auth != null",
      ".write": false
    },
    "products": {
      ".read": true,
      ".write": "auth != null && root.child('admins').child(auth.uid).val() === true"
    },
    "categories": {
      ".read": true,
      ".write": "auth != null && root.child('admins').child(auth.uid).val() === true"
    },
    "orders": {
      ".read": "auth != null && root.child('admins').child(auth.uid).val() === true",
      ".indexOn": ["createdAt","status"],
      "$orderId": {
        ".write": "(auth != null && root.child('admins').child(auth.uid).val() === true) || (!data.exists() && newData.exists())",
        ".validate": "newData.hasChildren(['customerName','phone','district','address','productId','total','status'])",
        "customerName": { ".validate": "newData.isString() && newData.val().length > 0 && newData.val().length < 100" },
        "phone": { ".validate": "newData.isString() && newData.val().length >= 6 && newData.val().length < 20" },
        "total": { ".validate": "newData.isNumber() && newData.val() >= 0" },
        "status": { ".validate": "auth != null || newData.val() === 'Pending'" }
      }
    },
    "customers": {
      ".read": "auth != null && root.child('admins').child(auth.uid).val() === true",
      ".write": "auth != null && root.child('admins').child(auth.uid).val() === true"
    },
    "settings": {
      ".read": true,
      ".write": "auth != null && root.child('admins').child(auth.uid).val() === true"
    }
  }
}

Notes: (1) the orders rule lets a visitor create a brand-new order but never modify or delete one that already exists — only an allow-listed admin can update status. (2) admins is admin-readable and never client-writable, so access can only be granted via the Firebase Console or Admin SDK — a client can never self-promote. (3) Keep product photos reasonably small (the editor auto-compresses uploads) since Realtime Database performs best with compact string values. (4) For extra hardening in production, add Firebase App Check.
